## Offen

1. Webhooks/Alarme bleiben at-least-once: wenn der Empfänger die Wirkung annimmt und die Verbindung vor der Antwort abbricht, wird nach Backoff erneut gesendet. Die API liefert eine stabile Delivery-ID, aber erzwingt keine Empfänger-Deduplizierung.
2. Magic-Link-Anfragen und UI-Posts ohne Idempotency-Key sind bewusst wiederholbare Create-Vorgänge. Eine automatische Inhalts-/Empfänger-Deduplizierung würde das Normalverhalten ändern.

## GELIEFERT / VERIFIZIERT WIE / OFFEN

GELIEFERT: Portal-Session-Idempotenz für denselben Workspace innerhalb einer Minute; Bericht mit Belegen für alle sechs Pfade.

VERIFIZIERT WIE: `npx tsc --noEmit` rc=0; `npm run build` erfolgreich; `npm run verify:all` PASS; `npm run verify:http` PASS; neuer Guard-Test PASS. Keine echten Provider-Aufrufe, Mails oder Produktionsdaten verwendet.

OFFEN: At-least-once-Webhooks/Alarme, wiederholte Magic-Link-Anfragen und Create-Aufrufe ohne Idempotency-Key wie oben begründet.
